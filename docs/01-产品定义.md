# 01 · 产品定义

## 一句话

把「28 款二次元手游的当期卡池 / 活动起止」做成一枚**常驻 Windows 11 任务栏左侧**的小组件：
不用打开浏览器、不用切窗口，扫一眼就知道哪款游戏快结束了、还剩多久。

## 目标用户

- 同时在玩多款二游、经常错过卡池 / 限时活动的玩家；
- 希望"信息常驻但别占桌面"的人（相比桌面挂件，任务栏更不挡内容）；
- 现有 DSH 插件 / 浏览器扩展的用户——他们已经在用同一套数据核心，桌面端是同一产品的第三种形态。

## 形态与位置

| 位置 | 说明 | 版本 |
|---|---|---|
| **任务栏左侧常驻条** | 一枚圆角胶囊，横向排 1–6 个"最近结束"的卡池 / 活动与倒计时；不抢焦点、不进 Alt+Tab | v0.1 |
| **展开面板** | 点常驻条弹出完整列表（28 款，按设置显隐/排序），沿用浏览器扩展的信息结构 | v0.1 |
| **系统托盘** | 图标 + 右键菜单：打开面板、显隐常驻条、设置、重读数据、退出 | v0.1 |
| 任务栏"小组件"按钮位置 | 与 Windows 原生小组件同区，建议在系统设置里关掉原生小组件；常驻条可配置左右偏移 | v0.1.7 |
| 多显示器 / 副屏任务栏 | 每块任务栏各显示一份（或仅主屏，可配置） | v0.1.8 |
| 官方 Widgets Board 小部件 | 走 Windows App SDK Widget Provider，作为"手机式小组件"补充入口 | 观察项 |

## v1 做什么（范围）

**必须（MUST）**

1. 任务栏左侧常驻条：显示"最近结束的 N 个卡池/活动 + 短倒计时"，点击展开面板。
2. 完整面板：28 款游戏（默认隐藏 5 款），卡池/角色、卡池起止、活动、活动起止四类信息；
   悬停显示池名 / 活动名与源站原文时间。
3. 数据准确复用 `gacha-calendar-core`，不在桌面端重写解析器。
4. 失败降级可见：某列抓取失败时显示"卡池失败：原因"或"沿用旧数据"，不静默错。
5. 托盘 + 设置 + 开机自启 + 单实例。
6. 多显示器 / 高 DPI / 任务栏自动隐藏 / 全屏游戏让位 的基本正确性。

**应该（SHOULD）**

- 应用内刷新（不依赖用户装 Node）；
- 显示哪些游戏、排序、常驻条条数可配置；
- 深浅色跟随系统；
- 便携版 + 安装包 + 自动更新检测。

**不做（v1 明确不做）**

- 不做账号体系、不绑定游戏账号、不读取游戏内存；
- 不做推送 / 提醒弹窗（先保证"看一眼"的静态价值）；
- 不做服务端聚合（每个客户端自己抓，见 [05-风险与合规](05-风险与合规.md)）；
- 不注入 explorer、不替换系统任务栏（作为 v2 实验项单独评估）；
- 不内置游戏图标资源（图标版权归原权利方；v0.1 用文字 + 色点，后续再评估外链/本地缓存方案）。

## 与三个仓库的关系

```
dsh-gacha-calendar（上游）
  ├─ DSH 桌面端插件（dsh-gacha-calendar npm 包）
  └─ packages/core/ → gacha-calendar-core npm 包   ← 抓取/解析/缓存合并的唯一真源
          │
          ├─ gacha-calendar-extension（浏览器扩展）
          └─ gacha-calendar（本仓库：Windows 任务栏小组件）
```

**明确边界**：抓取逻辑只在 core 里改；本仓库升级 `gacha-calendar-core` 版本即可获得新游戏/新解析器。
桌面端只做三件事：**实现 transport/storage**、**画界面**、**把窗口放到任务栏上**。

## 成功标准（v1 验收）

- 冷启动 ≤ 2s 出内容（读本地快照，不联网）；
- 空闲内存 ≤ 120MB、常驻条 CPU ≤ 0.1%（不刷新时）；
- 任务栏重排 / 改分辨率 / 显隐任务栏 / 切换深浅色 后 2s 内自动归位；
- 抓取失败时用户能一眼看出是哪一侧、什么原因，而不是看到过期数据当作最新；
- 卸载后不留注册表垃圾（开机自启项随卸载清理）。
