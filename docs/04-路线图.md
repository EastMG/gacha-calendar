# 04 · 路线图

> 原则：**每个版本都要能跑、能验证、能回退**。v0.1 不追求功能多，先把"任务栏常驻 + 真实数据"立住。
>
> **版本号策略（2026-10-21 用户确认）**：持续在 `0.1.x` 内递增（0.1.7、0.1.8 …），
> **不升 0.2.0**；新的 minor / 1.0 只有在用户明确指令时才考虑。

## 发布纪律

- 代码改动升版本号（`GachaCalendar.csproj` 的 `<Version>`），纯文档不动版本；
- `git tag` / GitHub Release 只在用户当轮明确点名时做；
- 每个 Release 说明按 `type: vX.Y.Z` 首行 + `- ` 分条 + "验证：" 收尾，与姊妹仓库一致。
