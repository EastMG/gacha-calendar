## v0.1.1 · 壳无关基础层（2026-10-21）

外壳技术栈未定，先把不依赖外壳的基础功能落地（详见 [07-壳无关基础层](07-壳无关基础层.md)）。

- [x] `config.json` schema：显隐三态（`hidden` / `shown` / `defaultHidden`）、排序、删除、
      自定义条目/来源、刷新间隔；归一化与校验；原子写
- [x] `packages/engine/`：配置、快照构建、文件存储 service、JSON-lines Host 协议
- [x] `tools/refresh.mjs` 改走同一套配置/快照/传输层，快照新增可选的 `config` 字段
- [x] 单进程测试入口（规避受限沙箱 spawn EPERM）：15 项 config/snapshot/service/host 用例
- [x] CI 增加 `engine` job；身份检查 job 继续生效

**验收**：`npm test` 15/15；改 config 后重抓，快照的排序/显隐与 config 一致；Host 可收发 JSON 命令。

## v0.1.2 · 刷新调度与失败退避（2026-10-21）

- [x] `service.refreshIfDue()`：按 `autoRefresh` / `refreshMinutes` / 上次成功时间判断是否该刷
- [x] 失败指数退避（5m → 15m → 45m … 上限 6h），成功后清零；状态持久化在 `cache.json`
- [x] 并发保护：同一时刻只允许一轮；手动 `refresh()` 绕过退避
- [x] Host 新增 `refreshIfDue` / `getStatus` 方法；外壳不再自己算调度
- [x] 新增 3 项调度测试（首次 due / 退避 / 并发），总计 18 项

**验收**：`npm test` 18/18；Host 连续调用 `refreshIfDue` 不会重复联网；失败后状态可跨进程恢复。

## v0.1.3 · 只读校验、诊断与 CLI（2026-10-21）

- [x] `validate.mjs`：snapshot 契约校验（schema、字段类型、失败三态、重复 id、时间戳、可见条目缺记录 warning）
- [x] `diagnostics.mjs` + `service.getDiagnostics()`：配置/快照/文件/调度状态一屏只读诊断
- [x] Host 新增 `getDiagnostics` / `validateConfig` / `validateSnapshot`
- [x] 壳无关 CLI：`status` / `config get|set` / `refresh [--if-due]` / `validate` / `diagnostics` / `info`
- [x] 测试 18 → 21 项；`npm run check` 覆盖新增入口

**验收**：CLI 实际跑通（隐藏 `genshin` 后强制刷新 → 22 个可见条目、校验通过）；`validate` 对坏快照返回非 0。

## v0.1.4 · 设置基础操作（2026-10-21）

- [x] Service：`listEntries` / `setEntryVisibility`（自动维护 `shown`）/ `setOrder` / `removeEntry` / `restoreEntry`
- [x] Host 对应五个方法；CLI 新增 `entries` / `show` / `hide` / `order` / `remove` / `restore`

**验收**：CLI 实测 28 条目 / 23 可见 / 5 出厂隐藏；hide genshin、show bh3、order、remove/restore 均生效。

## v0.2 · 应用内刷新（下一个版本）

目标：**普通用户不装 Node 也能持续更新数据**。

- [ ] CoreHost：隐藏 WebView2 加载 core，transport → HttpClient，storage → JSON 文件
- [ ] 刷新调度：启动判定（`lastRefresh`）、定时、失败退避、并发锁、手动刷新按钮
- [ ] 设置页补齐 core 配置：显隐（`hidden`/`shown`）、顺序、卡池/活动来源选择、自定义条目
- [ ] 刷新状态可见：面板顶部"成功 N/M + 分类"，悬停看逐条原因
- [ ] 快照写入原子化（临时文件 + rename），崩溃不坏档
- [ ] 版本升级后首启强制刷新（沿用 core 的 `lastVersion` 哨兵思路）
- [ ] 抓取请求的 URL 白名单/私有网段拦截（自定义条目）

**验收**：断开网络启动不崩、显示上次数据；恢复网络后下一轮自动成功；刷新失败不会把旧值刷成新时间。

## 发布纪律

- 代码改动升版本号（`GachaCalendar.csproj` 的 `<Version>`），纯文档不动版本；
- `git tag` / GitHub Release 只在用户当轮明确点名时做；
- 每个 Release 说明按 `type: vX.Y.Z` 首行 + `- ` 分条 + "验证：" 收尾，与姊妹仓库一致。
