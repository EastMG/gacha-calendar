# 05 · 风险与合规

## 1. 数据抓取合规

| 风险 | 说明 | 缓解 |
|---|---|---|
| 源站 ToS / robots | 数据来自各游戏官方公告、官方 Wiki、第三方站；不同站点条款不同 | 只读公开页面/接口、控制频率、不绕过登录/付费墙；收到权利人通知即下架对应来源；README 明确"信息聚合展示"定位 |
| 请求频率 | 桌面端每个用户各自抓，没有中心服务器；但单用户也可能频繁刷新 | 默认 6h 一次 + 失败退避；手动刷新限流；不并发刷全部 28 条（沿用 core 的调度） |
| 数据准确性 | 解析器依赖源站结构；源站改版会静默失败 | core 的三态语义（normal / nomatch / down）+ stale 提示；`parserVersions` 便于定位"哪版解析器坏了" |
| 时区/跨年 | 展示文本是源站墙钟；海外用户看国服时倒计时可能偏 | 文档写明；v0.1.7 可给 Result JSON 增加绝对结束时间戳 |
| 版权 | 游戏名、角色名、活动名、图标版权归原权利方 | 只展示名称与时间（信息性使用）；v0.1 不内置图标资源；如权利人异议即移除 |

**不做服务端聚合**是有意的：每个客户端用自己的 IP 请求，避免"我们的服务器被源站封了导致全体用户挂掉"的单点，
也让隐私政策可以写成"不收集任何用户数据"。

## 2. Windows 平台风险

| 风险 | 级别 | 说明 | 缓解 |
|---|---|---|---|
| 任务栏几何/行为变化 | 中 | Windows 更新可能改任务栏实现 | 只用公开窗口 `Shell_TrayWnd` + 公开样式；找不到任务栏时退回工作区底部；失败不崩 |
| 注入方案（v2 实验） | 高 | XAML Diagnostics 是私有 API，更新即可能失效；存在稳定性/杀软风险 | 不作为默认形态；兼容性检查 + 失败自动禁用 + 可清理；单独分支 |
| 多显示器 / DPI / 自动隐藏 | 中 | 边界多 | 物理像素定位 + PerMonitorV2 + 每秒重查 + 全屏让位；v0.1.8 系统化补测 |
| 杀软误报 / SmartScreen | 中 | 无签名、常驻、自启的桌面程序容易被拦 | 开源可审计；提供 SHA-256；尽早代码签名；不写敏感目录/不常驻高权限 |
| explorer 重启 | 低 | 任务栏窗口重建 | 每秒重查 `Shell_TrayWnd`，自动归位；面板位置重新计算 |
| 开机自启残留 | 低 | 卸载后注册表 Run 项仍在 | 安装包卸载时清理；设置里可一键关闭 |

## 3. 安全

- **不读取游戏进程/内存、不注入游戏客户端、不修改游戏文件**。
- **自定义来源 URL**（v0.1.7）只允许 `http/https`，拒绝 `file:`、`javascript:`、私有网段与本机地址，
  避免用户被诱导把桌面端当内网请求器。
- **无账号、无 Cookie、无凭据**：不触碰用户的任何登录态。
- **更新完整性**：v0.1.9 起发布物提供 SHA-256；若做自动更新，必须校验哈希/签名。
- **日志**只写本地，用户主动提供才用于排障；不含 URL 查询参数中的敏感值（v0.1.7 审查）。

## 4. 隐私

本产品**不收集、不上传任何用户数据**，没有遥测、没有崩溃上传、没有广告 SDK。

- 本地保存：设置、最近一次抓取结果、日志（在本机 `%LOCALAPPDATA%\GachaCalendar`）。
- 卸载：用户手动删除数据目录；安装包卸载时可选"保留/删除数据"。
- 若未来引入更新检查，只请求 GitHub Releases 公共接口，不携带用户标识。

## 6. 分发

| 渠道 | 风险/限制 | 计划 |
|---|---|---|
| GitHub Releases | 中国大陆下载可能慢 | v0.1.9 起提供 zip + 安装包，README 给镜像/加速建议 |
| Microsoft Store | 需 MSIX、签名、商店审核；小组件类目需确认政策 | v0.1.10 评估 |
| 国内软件站 | 二次打包/捆绑风险 | 不做；只发布官方 GitHub 产物 |
| 自动更新 | 安全与合规成本 | 只做"提示新版本 + 手动下载"，不做静默更新 |

## 7. 维护风险

- **单人维护 + 28 个来源**：源站改版是常态。缓解：解析器集中在 core（只修一处）；
  `selfCheck()` 提供来源健康度；用户可切备选源。
- **版本漂移**：本仓库依赖 npm 版 core；若 npm 落后于 main，桌面端拿不到最新修复。
  约定：发版前核对 `coreVersion`，必要时临时用本地 tarball 验证。
- **无服务端无法远程修**：旧版本用户会各自坏掉。缓解：界面显示"某列失败/沿用旧数据"；
  更新提示；`parserVersions` 便于用户反馈时定位。
