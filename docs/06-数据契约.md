# 06 · 数据契约

本文件冻结**本仓库与 `gacha-calendar-core` 之间的数据形状**。
改结构必须同时改这里并升 `snapshot.schemaVersion`；新增字段允许（消费方应忽略未知字段）。

## 1. 本地快照 `snapshot.json`

由 `tools/refresh.mjs` 生成；`data/snapshot.json` 是运行期文件（不入库），
`data/sample-snapshot.json` 是随仓库提交的示例（也被编译进程序作为内置兜底）。

```jsonc
{
  "schemaVersion": 1,              // 快照文件格式版本（不是 core 的 Result schemaVersion）
  "generatedAt": 1792535009364,    // 生成本文件的时间（毫秒）
  "coreVersion": "0.12.5",         // 生成时使用的 gacha-calendar-core 版本
  "config": { /* 归一化后的 config.json，见 docs/07 */ },
  "games": [                       // 条目元信息，顺序 = 展示顺序
    {
      "id": "genshin",
      "name": "原神",
      "hidden": false,             // 是否隐藏（已按 core 口径算好，见 §4）
      "defaults": {                // 无缓存时的静态默认值
        "banner": "", "roles": "", "bannerDates": "",
        "event": "", "eventDates": ""
      }
    }
  ],
  "result": {                      // 原样保存 core 的 Result JSON（见 §2）
    "schemaVersion": 1,
    "refreshedAt": 1792535009000,
    "parserVersions": { "genshin": 1, "nte": 2 },
    "games": { "genshin": { /* GameRecord，见 §3 */ } }
  }
}
```

字段约束：

| 字段 | 类型 | 说明 |
|---|---|---|
| `schemaVersion` | int | 当前为 `1`；结构不兼容变更时 +1 |
| `generatedAt` | long | Unix 毫秒 |
| `coreVersion` | string | 例如 `0.12.5`，用于排障 |
| `config` | object | 归一化后的用户配置（可选；外壳可忽略）。见 [07-壳无关基础层](07-壳无关基础层.md) |
| `games[].id` | string | core 的条目 id（稳定标识） |
| `games[].name` | string | 展示名（可能含服务器后缀，如「蔚蓝档案·国服」） |
| `games[].hidden` | bool | **已经算好的最终可见性**；桌面端不应自行再套一套规则 |
| `games[].defaults` | object | 内容字段默认值（空串表示无） |
| `result` | object | core Result JSON 原样透传 |

## 2. `result`（gacha-calendar-core 的 Result JSON，`schemaVersion: 1`）

```jsonc
{
  "schemaVersion": 1,
  "refreshedAt": 1792535009000,
  "parserVersions": { "genshin": 1, "hsr": 1, "nte": 2 },
  "games": {
    "genshin": {
      "name": "原神",
      "banner": "「虚星临渡」107期角色活动祈愿",
      "roles": "丝柯克、爱可菲",
      "bannerDates": "10-13 18:00 ~ 11-03 14:59",
      "bannerDatesRaw": "2026/10/13 18:00 ~ 2026/11/03 14:59",
      "bannerHover": "……多行明细（若来源提供）",
      "event": "「往冥府的安魂歌」",
      "eventDates": "10-13 18:00 ~ 11-03 14:59",
      "eventDatesRaw": "……",
      "eventHover": "……",
      "gachaFail": null,
      "eventFail": null,
      "gachaStale": false,
      "eventStale": false,
      "okAt": 1792535009000
    }
  }
}
```

### 2.1 内容字段（恒在，缺失为空串）

`banner` / `roles` / `bannerDates` / `bannerDatesRaw` / `bannerHover` /
`event` / `eventDates` / `eventDatesRaw` / `eventHover`

- `*Dates` 是**展示用短文本**（`MM-dd HH:mm ~ MM-dd HH:mm`），可能来自源站墙钟；
- `*DatesRaw` 是源站原文时间（悬停用）；
- `*Hover` 是多行明细（触摸端可点开；桌面端作 tooltip）。

### 2.2 状态字段（三态，核心语义）

| 字段 | 值 | 含义 | UI 口径 |
|---|---|---|---|
| `gachaFail` | `null` | 正常拿到当期 | 正常展示 |
| | `{ "kind": "nomatch" }` | 请求成功，但源站**没有当期内容** | 「新卡池未公布」（算成功） |
| | `{ "kind": "down", "reason": "HTTP 403" }` | 抓取或解析**报错** | 「卡池失败：HTTP 403」 |
| `eventFail` | 同上 | 活动侧 | 同上 |
| `gachaStale` / `eventStale` | bool | 该列显示的是沿用的上次成功值 | 行尾/悬停标「沿用旧数据」 |
| `okAt` | long | 最近一次"该条目两侧都拿到新数据"的时间 | 游戏名悬停显示刷新时间 |
| `skipped` | bool（可选） | 该条目本轮被跳过（未配置来源/隐藏） | 不计入成功数 |

> **不要**把"某一侧未配置来源"并进 `down`：那是合法状态（见 core README）。

### 2.3 `parserVersions`

每个内置条目一个数字，表示该条目**解析逻辑**的版本；源站改版修解析器时 +1。
用途：用户反馈时无服务端也能定位"坏的是哪个版本、哪款游戏"。

## 3. `games` 的顺序与展示

- 快照里的 `games[]` 顺序 = 工具按 `order` 配置排序后的结果（未配置则 core 默认顺序）；
- 桌面端按数组顺序渲染，不再自行排序；
- 常驻条只取"当前有进行中的卡池或活动"的条目，按**最近结束时间**升序取前 N 个（N 可配 1–6）。

## 4. 可见性规则（生成快照时已落地）

core 的隐藏是三态，不是单纯 `hidden` 数组：

```
hidden 包含 id                      → 隐藏
条目有 defaultHidden 且 shown 不含 id → 隐藏
否则                                → 显示
```

`tools/refresh.mjs` 的实现：

```js
const sources = new Map(engine.__test.SOURCES.map((s) => [s.id, s]));
const hidden = new Set(settings.hidden ?? []);
const shown = new Set(settings.shown ?? []);
const isHidden = (id) =>
  hidden.has(id) || (!!sources.get(id)?.defaultHidden && !shown.has(id));
```

> 当前 28 款里有 5 款出厂默认隐藏（崩坏3、OurNotes 日服/国际服、卡厄斯梦境、嘟嘟脸恶作剧）；
> 实际可见条目数见刷新输出（本轮为 23）。

## 5. core 使用的 storage 键（v0.2 接入 CoreHost 时照抄）

| 键 | 类型 | 用途 |
|---|---|---|
| `order` | string[] | 展示顺序 |
| `hidden` | string[] | 用户隐藏的条目 |
| `shown` | string[] | 出厂默认隐藏条目被用户打开后记在这里 |
| `removed` | string[] | 删除的条目 |
| `customEntries` | object[] | 自定义条目 |
| `customUrls` / `customEventUrls` | object | 卡池/活动自定义来源地址 |
| `gameColors` | object | 自定义条目颜色（可选） |
| `autoRefresh` / `refreshMinutes` | bool / int | 自动刷新开关与间隔 |
| `lastData` / `lastRefresh` / `lastSource` / `lastVersion` | 缓存 | 上次结果、时间、来源、生成该缓存的版本 |

桌面端 v0.1 只消费快照；v0.2 把上述键持久化到 `settings.json` 的一个命名段（或独立 `config.json`）。

## 6. 生成与校验

```powershell
cd tools
npm install
npm run refresh        # → ../data/snapshot.json
npm run sample         # → ../data/sample-snapshot.json（随仓库提交的示例）
npm run selfcheck      # 只跑来源自检，不写文件
node --check refresh.mjs
```

校验清单（发版前）：

- [ ] 刷新输出"成功 N/M"与 UI 面板顶部一致；
- [ ] `games[]` 数量 = 可见条目数（默认 23）；
- [ ] 至少一条 `gachaFail.kind === "down"` 的夹具能正确显示失败原因（用旧快照或断网模拟）；
- [ ] `refreshedAt` / `generatedAt` 为合理时间；
- [ ] 跨年区间（`12-30 ~ 01-05`）的倒计时不出现负数/已结束误判。

## 7. 兼容性约定

- 消费方（桌面端）对**未知字段忽略**；对**缺失内容字段**按空串处理；对**缺失状态字段**按 `null` 处理。
- 新增**可选**字段不升版本；删除/改义字段必须升 `schemaVersion`。
- `snapshot.config` 是 2026-10-21 新增的可选字段（归一化后的用户配置），不升版本。
- `coreVersion` 与 `parserVersions` 只用于诊断，不参与 UI 逻辑。
- 数字时间戳统一 Unix 毫秒；展示时间字符串不保证可被严格解析（UI 解析失败时原样显示）。
