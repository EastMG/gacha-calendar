# 07 · 壳无关基础层（config / snapshot / host 协议）

> 背景：Windows 外壳还没最终拍板（WPF 还是 Tauri）。但**数据、配置、刷新、快照**这些基础功能
> 不应该被外壳选型阻塞。本文定义这层"壳无关"的边界与协议，并说明它已经在仓库里落地。
>
> 一句话：**外壳只负责"窗口和任务栏"，其余逻辑全部下沉到 `packages/engine/`。**

## 1. 分层

```
┌────────────────────────────────────────────────────────────┐
│ 外壳（shell-specific，未定）                                 │
│   WPF：Win32 任务栏停靠 / 托盘 / 设置窗 / 单实例 / 自启       │
│   Tauri：Rust 窗口/托盘 + WebView2 前端（未来可切换）         │
└───────────────────────────┬────────────────────────────────┘
                            │ 读快照 / 读写配置 / 触发刷新
┌───────────────────────────▼────────────────────────────────┐
│ packages/engine（壳无关，Node 参考实现）                      │
│   config.mjs     配置 schema、归一化、可见性三态、排序         │
│   snapshot.mjs   core 结果 + 配置 → snapshot.json             │
│   service.mjs    core + 文件存储（config/cache/snapshot）     │
│   host.mjs       JSON-lines Host：stdin/stdout 命令协议       │
│   transport.mjs  Node fetch 版 core transport                │
└───────────────────────────┬────────────────────────────────┘
                            │ import（npm 依赖）
┌───────────────────────────▼────────────────────────────────┐
│ gacha-calendar-core（唯一抓取真源，28 款）                    │
└────────────────────────────────────────────────────────────┘
```

外壳技术栈只影响最上层；**只要 host/snapshot/config 协议不变，换外壳不需要改数据层**。

## 2. 配置 `config.json`

位置：由外壳决定（开发期 `data/config.json`；安装版建议 `%LOCALAPPDATA%\GachaCalendar\config.json`）。
`data/config.json` 被 `.gitignore` 忽略；`data/config.example.json` 是提交的默认样例。

```jsonc
{
  "schemaVersion": 1,
  "order": [],                 // 展示顺序（id 数组；未列出的保持默认顺序）
  "hidden": [],                // 用户隐藏的条目
  "shown": [],                 // 出厂默认隐藏条目被用户打开后记这里
  "removed": [],               // 已删除的内置条目
  "customEntries": [],         // 自定义条目（对象数组）
  "customUrls": {},            // 卡池来源覆盖：{ id: "https://..." }
  "customEventUrls": {},       // 活动来源覆盖：{ id: "https://..." }
  "gameColors": {},            // 每游戏主题色：{ id: "#rrggbb" }
  "autoRefresh": true,
  "refreshMinutes": 1440       // 60 .. 60480（1 小时 .. 42 天）
}
```

### 2.1 与 core 的 storage 差异（**最容易错的地方**）

core 的 storage 里 `customEntries` / `customUrls` / `customEventUrls` / `gameColors` 是
**JSON 字符串**（历史约定），而 config.json 用对象/数组。转换只在 `toEngineSettings()` 做：

```js
customUrls: JSON.stringify(config.customUrls)
customEntries: JSON.stringify(config.customEntries)
```

**不要**在 UI 或 service 里各自手写 `JSON.stringify`，否则会出现"设置页改了、引擎读不到"的经典 bug。

### 2.2 可见性三态

```
hidden 包含 id                      → 隐藏
条目有 defaultHidden 且 shown 不含 id → 隐藏
否则                                → 显示
```

`visibilityPatch(config, id, visible, defaultHidden)` 负责同时维护 `hidden` / `shown`，
避免"出厂隐藏项勾了不生效"。

### 2.3 归一化

`normalizeConfig()` 保证：

- 缺字段补默认值；
- `order/hidden/shown/removed` 去重、去空；
- `refreshMinutes` 裁剪到 60..60480；
- 未知字段保留（向前兼容，不丢用户数据）。
- 配置坏了不让应用崩：`loadConfigFile()` 文件不存在 → 默认配置；JSON 损坏 → 抛错，由外壳决定回退。

## 3. 快照 `snapshot.json`

在原有字段上**新增 `config`**（只读回显，方便外壳不读第二个文件就能显示当前配置）：

```jsonc
{
  "schemaVersion": 1,
  "generatedAt": 1792535009364,
  "coreVersion": "0.12.5",
  "config": { /* 归一化后的 config.json */ },
  "games": [
    { "id": "genshin", "name": "原神", "hidden": false, "defaults": { /* ... */ } }
  ],
  "result": { /* core Result JSON，schemaVersion=1 */ }
}
```

这是**新增可选字段**，不升 `snapshot.schemaVersion`；旧外壳忽略 `config` 即可。
完整字段见 [06-数据契约](06-数据契约.md)。

## 4. Host 协议（JSON lines）

参考实现：`packages/engine/host.mjs`。启动：

```powershell
node packages/engine/host.mjs --data-dir data
```

每行一个 JSON：

```json
{"id":1,"method":"hello","params":{}}
{"id":2,"method":"getConfig"}
{"id":3,"method":"updateConfig","params":{"patch":{"hidden":["genshin"]}}}
{"id":4,"method":"refresh"}
```

响应：

```json
{"id":1,"ok":true,"result":{"protocol":1,"coreVersion":"0.12.5","dataDir":"..."}}
{"id":1,"ok":false,"error":{"code":"unknown-method","message":"未知方法：foo"}}
```

| 方法 | 参数 | 返回 |
|---|---|---|
| `hello` | — | `{ protocol, coreVersion, dataDir }` |
| `getConfig` | — | 归一化后的 config |
| `updateConfig` | `{ patch }` 或直接给 config 对象 | 更新后的 config |
| `listGames` | — | core 的条目元信息 |
| `getCached` | — | core 的 Result JSON（上次缓存） |
| `refresh` | — | 抓一轮 → 写 snapshot → 返回 snapshot |
| `getSnapshot` | — | 最近一次写入的 snapshot（无则 null） |
| `selfCheck` | — | 解析器自检报告（只读） |
| `shutdown` | — | `{ bye: true }`，随后进程退出 |

约定：

- **stdout 只允许协议 JSON**；日志写 stderr；
- 请求串行处理（避免并发 refresh）；
- 错误码：`bad-json` / `unknown-method` / `invalid-config` / `error`。

## 5. 两种外壳怎么接

### 5.1 如果最终选 WPF（当前原型）

- 直接读 `snapshot.json` 显示（现状）；
- 配置编辑：可以调 Host（启动 Node 子进程），也可以在 C# 里实现同一套 config schema；
- 建议 v0.2 先用 **Node sidecar + JSON-lines**，等确认 WPF 后再决定是否全 C# 化。

### 5.2 如果最终选 Tauri

- Rust 侧启动同一个 Host 作为 sidecar，或把 `packages/engine` 的纯逻辑直接放进 WebView2（浏览器 storage 版本）；
- 前端直接消费 snapshot / config；
- 任务栏窗口/托盘/自启换成 Tauri 的插件实现。

两条路都不需要重写 `config.mjs` / `snapshot.mjs` 的规则。
